# Implementation guidance

## Scope and map

Applies to `src/` and its descendants, alongside the root `AGENTS.md`. There is currently one project: `BookStore.Api`.

| Area within `BookStore.Api/` | Responsibility |
| --- | --- |
| `Program.cs` | Composition: configuration, DI, pipeline, migrations in Development, and endpoint mapping. |
| `Endpoints/` | HTTP, route groups, binding, validation filter, and typed results. |
| `Contracts/` | `BookRequest` and `BookResponse`: public input and output shapes. |
| `Services/` | `IBookService` and `BookService`: catalog operations, mapping, and persistence coordination. |
| `Models/` | The `Book` entity mapped by EF Core. |
| `Data/` | `BookStoreContext` and relational model configuration. |
| `Data/Migrations/` | Versioned schema history and snapshot generated by EF Core. |
| `Properties/` | Local launch profile in `launchSettings.json`. |
| `appsettings*.json` | Application and environment configuration; no real credentials. |
| `BookStore.Api.http` | Manual HTTP contract examples, complemented by automated tests in `tests/`. |

## Dependencies and boundaries

- Endpoints use contracts and `IBookService`; keep EF Core queries and writes in the service.
- The service uses contracts, models, and the context; endpoints or filters choose HTTP status codes.
- `Data` maps `Models`; `Models` and `Contracts` must not depend on endpoints, services, or the context.
- Folders organize a single assembly: these boundaries are conventions, not compiler-enforced isolation.
- `Program.cs` connects the parts. Do not introduce production references to `tests/`.

## Changes and validation

- Use appropriate asynchronous operations and propagate `CancellationToken`; do not share a `DbContext` across parallel operations.
- In this .NET 8 project, run Data Annotations through the filter; OpenAPI metadata does not validate input.
- Keep POST/PUT consistent with the complete contract, errors in Problem Details, and `Location` on creation.
- Generate a new migration for schema changes; do not rewrite applied migrations to accommodate a new decision.
- Keep automatic migrations and Swagger restricted to Development; other environments apply migrations separately.
- Verify behavior changes with `dotnet test BookStore.sln`; review `.http`, README, and teaching guide when affected.

## Evolution

Keep the CRUD API in one project while this organization meets its needs. Before extracting an area, explain which actual coupling it reduces and how contracts and tests remain valid.
Generic repositories, CQRS, distributed services, and organization by feature are not current requirements. Future adoption should follow a demonstrated need and a recorded decision.
