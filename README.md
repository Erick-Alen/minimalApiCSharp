# BookStore Minimal API

A book CRUD API built with C# and ASP.NET Core 8, based on [Clifftech's tutorial](https://dev.to/clifftech123/learn-minimal-apis-in-net-8-full-crud-tutorial-for-beginners-1b86). It keeps the example's fields and operations, with small improvements to local setup and HTTP responses.

For a guided explanation, see the [25-minute Minimal API walkthrough (Brazilian Portuguese)](docs/minimal-apis-fluxo-basico.md), including a diagram, real code examples, and a demonstration.

Implemented decisions are recorded in the [ADR index](docs/adr/README.md). Maintenance guidance lives in the `AGENTS.md` files for the [root](AGENTS.md), [src](src/AGENTS.md), [tests](tests/AGENTS.md), and [docs](docs/AGENTS.md). Future architecture changes remain open questions in the ADR index.

Technical documentation is maintained in English; the teaching guide is maintained in Brazilian Portuguese.

## Run locally

Prerequisite: .NET 8 SDK.

```bash
dotnet restore
dotnet run --project src/BookStore.Api --launch-profile http
```

Open [Swagger](http://localhost:5043/swagger/index.html) to try the endpoints. In `Development`, the application automatically applies migrations and creates `src/BookStore.Api/books.db`. The catalog starts empty; books remain in the database after restarting the API.

## Endpoints

| Method | Route | Result |
| --- | --- | --- |
| GET | `/api/v1/books` | `200` with a list; `[]` when empty |
| GET | `/api/v1/books/{id}` | `200` with the book or `404` |
| POST | `/api/v1/books` | `201` with the book and a `Location` header |
| PUT | `/api/v1/books/{id}` | `200` with the updated book or `404` |
| DELETE | `/api/v1/books/{id}` | `204` with no body or `404` |

IDs are GUIDs generated by the API. `PUT` replaces all fields and preserves the ID; it does not create a missing book. Collection routes also accept a trailing slash.

Create a book:

```bash
curl -i http://localhost:5043/api/v1/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"Dom Casmurro","author":"Machado de Assis","description":"Romance brasileiro.","category":"Romance","language":"Português","totalPages":256}'
```

[BookStore.Api.http](src/BookStore.Api/BookStore.Api.http) contains the full workflow for the VS Code REST Client extension. Run the creation request before requests that use its returned ID.

All fields are required. Title and author allow up to 200 characters; description, 4,000; category, 100; language, 50. Empty strings, whitespace-only strings, and `null` are rejected. `totalPages` must be a positive integer. Leading and trailing whitespace is removed when saving text. Invalid field values return `400` with field errors in `application/problem+json`.

## Organization and decisions

- `Contracts`: a request contract shared by POST and PUT, plus a response contract that does not expose the database entity.
- `Models` and `Data`: the entity, EF Core context, and versioned migrations.
- `Services`: asynchronous operations, injected through `IBookService`, with request cancellation.
- `Endpoints`: grouped routes, typed responses, and a Data Annotations validation filter.
- `tests/BookStore.Api.Tests`: HTTP integration tests using isolated SQLite databases.

Compared with the tutorial, SQLite replaces SQL Server to avoid requiring an external server. Data Annotations and a filter validate POST and PUT without another validation dependency. An empty collection returns `200`; a missing book returns `404`, without business exceptions for these cases. Error handling uses ASP.NET Core Problem Details without exposing internal exception messages. Authentication, a frontend, and repository layers are outside the current scope.

## Tests

```bash
dotnet test
```

Tests cover the CRUD lifecycle, `Location`, persistence across restarts, missing IDs, creation and update validation, malformed JSON, and Swagger documentation. They use temporary databases and leave the development database untouched.

## Migrations and configuration

```bash
dotnet tool restore
dotnet ef database update --project src/BookStore.Api
```

To evolve the model, create a migration with `dotnet ef migrations add ChangeName --project src/BookStore.Api --output-dir Data/Migrations`. Run these commands from the solution root.

The connection is configured in `ConnectionStrings:Books` and can be overridden with the `ConnectionStrings__Books` environment variable, for example `Data Source=/absolute/path/books.db`. Relative SQLite paths are resolved against the API content root (`src/BookStore.Api` with the commands above). Outside `Development`, Swagger and automatic migrations are disabled; apply migrations before starting the API. The supplied HTTP launch profile is intended for local development.

Additional references: [ASP.NET Core 8 Minimal APIs](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis?view=aspnetcore-8.0&preserve-view=true) and [EF Core migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/).
